Points-Race Chess & Its Search AI

Chess without checkmate. Every capture scores points and the first player to 15 wins. I built the game in Python, wrote the AI that plays it, ported both to JavaScript so you can play it here, and ran the AI against itself 800 times to measure how the new rules change the game.

1The new rules

Traditional chess revolves around checkmate, which narrows strategy and makes the game hard to pick up. I wanted to see what happens to strategy when the win condition changes. In this version:

  • Every captured piece adds its point value to the capturer's score.
  • No check, no checkmate. The king can be captured without ending the game.
  • The first player to reach 15 points wins, shown on a live side-panel scoreboard.

Each side starts with 41 points of material, so winning means taking a little more than a third of your opponent's army. The queen alone is worth 60% of a win.

    4What the engine shows about the new rules

    Changing the win condition changes what good play looks like. To measure that, I had the AI play itself 800 times at fixed search depths. The search AI has no chess habits to unlearn: it only knows the moves, the point values, and that 15 wins. So its games show what the rules reward, without a human's instincts in the way.

    187 of 200games won by looking 4 moves ahead instead of 2The deeper search won 94% of the time, with the sides swapped on every opening.

    The king

    The king

    A king was captured in 28% of games, and it accounted for only 2% of winners' points. The engine treats it as the 2-point piece it is: worth guarding, but not worth losing a knight over.

    The queen

    The queen is 9 of the 15 points, so the game should revolve around winning it.

    The queen

    A queen was captured in only 39% of games. When one did fall, it usually decided the game: the side that took a queen first won 82% of those games.

    Moving first

    White won 56% of the 200 games. With this many games the margin of error is about 7 points, so any first-move edge is small.

    How I kept the numbers honest

    • Searches stop at a fixed depth, not after a time limit, so a faster or slower computer gives the same games.
    • All randomness comes from a seeded generator, so the script prints the same numbers every run.
    • These are games between copies of one engine. They show what this evaluation function does with the rules, not how people play them.

    Next: a learning agent

    The search AI is told what matters: I wrote its evaluation function by hand. The next stage is a reinforcement-learning agent that starts with only the rules and the reward and has to work out the rest from its own games. The numbers above are its benchmark. Does it learn to give up its king for a knight? Does it guard its queen as closely? And how many games does it need before it can beat a search that looks 2 moves ahead?

    5What I built

    Game development

    Designed and implemented the board, piece movement, rule enforcement, and user interaction in Python with Pygame.

    Rule-system redesign

    Removed the checkmate logic and replaced it with point tracking, which meant making the rule handling modular enough to change the win condition cleanly.

    User interface

    A side-panel scoreboard tracks both players' points in real time and declares the winner the moment someone reaches 15.

    Search AI

    Wrote a computer opponent that looks several moves ahead with minimax and alpha-beta pruning, follows captures to the end of each trade, and scores positions on material, the points race, and piece placement. It runs in a background thread on the desktop and a Web Worker in the browser.

    Browser port

    Rebuilt the rules, the AI, and the interface in plain JavaScript so the game runs on this page, with keyboard controls and three difficulty levels.

    Testing & measurement

    Wrote unit tests for the rules and the AI, including a move-count check against known values, and a seeded self-play script that produced the results above.

    Status
